# 남은 작업 전부 (순서대로 1 → 8)
표시: [직접] 내가 손으로 / [프롬프트] 안티그래비티 에이전트 창에 붙여넣기
프롬프트 하나가 끝날 때마다 화면(localhost:3000)에서 "확인할 것"을 눈으로 확인하세요.

## 1단계 [직접] 구글 시트와 Apps Script 고치기  ← 새로고침하면 숫자가 돌아오는 문제 해결
---------------------------------------------------------------
1. 구글 시트(도서관 시트)를 엽니다.
2. 아래쪽 탭 `대여기록` 의 1행(머리글)이 이렇게 되어 있는지 확인합니다. 다르면 이름만 맞춰 고쳐 주세요.
   신청시각 | 대여일 | 책 제목 | 번호/별명 | 반납예정일 | 반납여부
   (이미 다른 순서여도 괜찮아요. "책", "예정", "반납" 글자가 들어 있으면 코드가 알아서 찾아요. 단, `반납여부` 칸은 꼭 있어야 해요. 없으면 맨 오른쪽에 새로 만드세요.)
3. 메뉴 [확장 프로그램] → [Apps Script]
4. 왼쪽 코드 창을 클릭 → Ctrl+A (전체 선택) → Delete (전부 지우기)
5. `Apps스크립트_전체코드.txt` 파일을 안티그래비티에서 열어 Ctrl+A → Ctrl+C
6. Apps Script 코드 창에 Ctrl+V → Ctrl+S(저장)
7. 오른쪽 위 [배포] → [배포 관리] → 연필(✏) 아이콘 → 버전: [새 버전] → [배포]
   (URL은 그대로예요. `.env`는 고칠 필요 없어요.)
8. 브라우저 주소창에 웹 앱 주소(`.env`의 SHEET_URL 값)를 붙여 열어 보세요.
   `{"ok":true,"borrowedCounts":{...},"reviews":[]}` 처럼 나오면 성공입니다.
   `한줄평` 탭은 처음 한 줄 평이 들어올 때 자동으로 만들어져요.
9. 새로고침 확인: localhost:3000 에서 책을 한 권 빌리고 → 새로고침(F5) → 그 책의 남은 권수가 줄어든 채로 있는지 확인.
   * 선생님이 책을 돌려받으면 시트 `반납여부` 칸에 `반납` 이라고 쓰면 남은 권수가 다시 늘어요.
   * 시험으로 쌓인 대여 기록이 있으면 필요 없는 행은 시트에서 지우세요.

## 2단계 [프롬프트] 마감 임박 표시 + 한국 날짜 바로잡기
---------------------------------------------------------------
```
src/app/page.tsx 를 아래 두 가지만 고쳐 줘. 디자인 규칙은 design-handoff/HANDOFF.md 를 따르고, 다른 기능은 건드리지 마.

1. 날짜 오류 고치기: todayString() 과 daysLater() 가 toISOString() 을 써서 한국 시간 오전 9시 전에는 하루 전 날짜가 나와. 컴퓨터의 현지 날짜(getFullYear, getMonth, getDate)로 YYYY-MM-DD 를 만들도록 바꿔 줘.
2. 마감 임박 표시(수업 4장 내용): 남은 책이 1권이면 초록색 "남은 책 1권" 배지 대신 분홍 바탕(#FFE3EE)에 진한 장미색 글씨(#B3365B)로 "마감 임박 · 1권 남음" 을 보여 줘. 글꼴과 크기는 기존 배지와 같게. 0권이면 기존 "다 빌려갔어요", 2권 이상이면 기존 초록 배지 그대로.

끝나면 npm run lint 를 실행하고, 화면에서 확인할 점을 2줄로 알려 줘.
```
확인할 것: 남은 책이 1권인 책(예: 누가 내 머리에 똥 쌌어?)에 분홍 "마감 임박" 배지가 보인다.

## 3단계 [프롬프트] 서버가 남은 책을 직접 확인하기 (수업 6장: 서버가 계산)
---------------------------------------------------------------
```
src/app/api/rent/route.ts 의 POST 를 고쳐 줘. 수업에서 "결제 금액은 화면이 보낸 값이 아니라 서버가 계산한다"고 배웠는데, 같은 생각으로 "대여 가능한지는 화면 말고 서버가 확인"하게 하고 싶어. 다른 코드와 디자인은 건드리지 마.

1. data/books.js 의 initialBooks 를 불러와서, 받은 bookTitle 이 목록에 없으면 400 으로 "없는 책이에요." 를 돌려줘.
2. 시트에 저장하기 전에 SHEET_URL 로 GET 을 보내 지금 대여 중인 권수(borrowedCounts)를 읽어. 그 책의 대여 중 권수가 totalCount 이상이면 저장하지 말고 409 와 { ok:false, message: "앞서 다른 친구가 빌려 가서 지금은 빌릴 수 없어요." } 를 돌려줘. 시트 조회 자체가 실패하면 기존처럼 저장은 계속 진행해 줘.
3. page.tsx 는 이미 서버가 준 message 를 빌리기 창 안에 보여 주도록 되어 있으니, 409 일 때도 그 문구가 창 안에 나오는지만 확인하고, 안 나오면 최소한만 고쳐 줘.
끝나면 npm run lint 를 실행하고 결과를 알려 줘.
```
확인할 것: 정상 대여는 그대로 되고, 없는 책 이름으로 보내면 거절된다.

## 4단계 [프롬프트] 한 줄 평 쓰기 창 (얼굴 3개 + 30자)
---------------------------------------------------------------
```
계획서의 "한 줄 평" 기능 중 "쓰기" 부분을 만들어 줘. 디자인은 design-handoff/HANDOFF.md 의 5번(빌리기 창)과 같은 말투·색·모양을 따라. 기존 대여 기능과 상태는 건드리지 마.

1. 책 카드의 [빌리기] 버튼 아래에 작은 보조 버튼 "한 줄 평 쓰기" 를 넣어 줘. 높이 52px 이상, 흰 바탕 + 연보라 테두리(#D9D2F7) + 글씨 #4B3A8F, 둥글게. 다 빌려간 책에도 보여 줘(읽은 친구가 쓸 수 있게).
2. 누르면 "한 줄 평 창"(모달)이 열려. 바깥을 누르면 닫혀.
   - 맨 위: 작은 표지 + 책 제목(손글씨 28px) + "이 책 어땠어요?"
   - 이름 입력칸: "나는 누구예요?" (번호나 별명, 비면 안내 문구)
   - 표정 버튼 3개를 가로로 크게(각 96px 이상, 둥근 흰 카드): 😊 대신 SVG 얼굴로 그려 줘 — 웃는 얼굴 "좋아요"(민트 #CDEBDD), 무표정 "보통이에요"(노랑 #FFEFA8), 찡그린 얼굴 "아쉬워요"(분홍 #FFE3EE). 하나만 선택되고 선택되면 테두리 #7B5FE0 4px + 살짝 커지게. 표정을 안 고르면 보낼 수 없고 안내 문구를 창 안에 보여 줘.
   - 선택 글쓰기: "하고 싶은 말이 있으면 써 보세요 (선택)" 입력칸, 최대 30글자, 오른쪽 아래에 "12/30" 글자 수 표시.
   - 버튼: [취소] 와 [보내기](보내는 중에는 "보내는 중…").
3. [보내기] 는 fetch("/api/rent", POST) 로 { type:"review", date:오늘, bookTitle, borrower, rating:"좋아요"|"보통이에요"|"아쉬워요", comment } 를 보내.
4. src/app/api/rent/route.ts 의 POST 가 type 에 따라 나뉘게 해 줘.
   - type:"review" 면: borrower 가 비었거나, rating 이 위 세 값이 아니거나, comment 가 30자를 넘으면 400. 통과하면 시트로 { type:"review", date, bookTitle, borrower, rating, comment } 를 그대로 전달. (남은 책 확인은 대여일 때만 해.)
   - type:"rent" 는 기존 그대로.
5. 성공하면 같은 창 안에서 "고마워요! 선생님이 확인하면 모두에게 보여요." 와 [확인] 버튼을 보여 주고, 오류도 창 안에 문구로 보여 줘(alert 쓰지 마).
끝나면 npm run lint 를 실행하고, 확인할 점을 3줄로 알려 줘.
```
확인할 것: 한 줄 평을 보내면 구글 시트 `한줄평` 탭이 생기고 한 줄이 들어온다. `승인` 칸은 비어 있다.

## 5단계 [프롬프트] 승인된 한 줄 평 보기
---------------------------------------------------------------
```
이제 "한 줄 평 보기" 부분을 만들어 줘. 선생님이 구글 시트 `한줄평` 탭의 `승인` 칸에 O 를 쓴 글만 화면에 보이게 하는 거야. 시트 쪽 Apps Script 의 doGet 은 이미 { ok, borrowedCounts, reviews:[{bookTitle, borrower, rating, comment}] } 를 돌려줘(최신 글이 먼저, 승인된 글만).

1. src/app/api/rent/route.ts 의 GET 이 지금처럼 borrowedCounts 를 주면서, reviews 도 함께 { ok:true, borrowedCounts, reviews } 로 돌려주게 해 줘. reviews 는 각 항목에서 bookTitle, borrower, rating, comment 만 문자열로 골라 담고, rating 이 "좋아요/보통이에요/아쉬워요" 가 아니면 제외하고, comment 는 30자까지만 잘라서 줘.
2. page.tsx 는 처음 열릴 때 이미 GET 으로 대여 현황을 읽고 있으니, 같은 요청에서 reviews 도 받아 상태로 저장해 줘.
3. 책 카드: 그 책의 승인된 한 줄 평이 있으면, 작가 줄 아래에 작은 상자(연보라 바탕 #F6F2FF, 둥근 20px)로 가장 최근 1개를 보여 줘. 왼쪽에 표정 SVG 아이콘(28px), 오른쪽에 글(없으면 "좋아요" 같은 표정 이름), 맨 아래 작게 "– 별명". 한 줄 평이 2개 이상이면 오른쪽에 "더 보기 (N)" 버튼(높이 48px 이상). 한 줄 평이 없으면 상자를 아예 만들지 마.
4. "더 보기"를 누르면 "한 줄 평 모음" 창이 열려. 책 제목 + 승인된 글 목록(표정 아이콘, 글, 별명), 맨 아래 [닫기]. 목록이 길면 창 안에서 스크롤. 바깥을 누르면 닫혀.
5. 사용자 입력은 전부 React 가 문자로만 그리게 해(dangerouslySetInnerHTML 쓰지 마).
끝나면 npm run lint 를 실행하고, 확인할 점을 3줄로 알려 줘.
```
확인할 것: 시트 `한줄평` 탭의 `승인` 칸에 O 를 쓰고 새로고침하면 그 글이 카드에 나타난다. O 를 지우면 사라진다.

## 7단계 [프롬프트] GitHub 에 올리기
```
이 프로젝트(picture-book-library)를 GitHub 의 새 저장소 https://github.com/(내 아이디)/picture-book-library 에 올리고 싶어. 값(주소·키)은 채팅에 보여 주지 말고 이름만 알려 줘.

1. 먼저 git remote -v 로 지금 연결된 원격 저장소를 확인해서 알려 줘. skilltomoney-app 으로 연결돼 있으면 절대 push 하지 말고 나에게 먼저 물어봐.
2. .gitignore 에 .env 가 제외되는지 확인해 줘(.env* 도 괜찮아). git status 에 .env 가 나오지 않는지도 확인해 줘.
3. npm run build 가 오류 없이 끝나는지 확인해 줘. (오류가 나면 원인을 한 줄로 설명하고 고치기 전에 먼저 물어봐 줘.)
4. 명령을 실행하기 전에 각 명령이 무슨 뜻인지 한 줄씩 설명해 줘. 그다음 git init(필요하면), 커밋, 원격 저장소 연결, push 를 차례로 진행해 줘. 커밋 메시지도 제안해 줘.
5. 마지막에 .env 가 커밋에 들어가지 않았는지 확인하는 명령을 실행해 줘.
```
확인할 것: GitHub 저장소 페이지를 새로고침하면 파일이 보이고 `.env` 는 없다. 로그인 창이 뜨면 브라우저에서 승인하세요.

## 8단계 [직접] Vercel 배포  (수업 7장)
---------------------------------------------------------------
1. vercel.com 로그인(GitHub 계정) → [Add New...] → [Project]
2. `picture-book-library` 옆 [Import]
   * 목록에 안 보이면: "Adjust GitHub App Permissions" 를 눌러 새 저장소를 허용하세요.
3. Application Preset 이 Next.js 인지 확인, Root Directory 는 `./` 그대로
4. [Environment Variables] 를 펼쳐서
   Key = `SHEET_URL`   (대문자, = 없이)
   Value = 웹 앱 주소 `https://script.google.com/.../exec` (주소만. `SHEET_URL=` 은 빼고)
   Environments 는 그대로
   * 화면을 캡처해서 남에게 보낼 때는 Value 를 가리세요. 이 주소를 알면 누구나 시트에 글을 보낼 수 있어요.
5. [Deploy] → 1~2분 뒤 축하 화면
6. [Visit] 으로 열어 확인: 첫 화면, 책 카드, 빌리기 → 시트에 한 줄 추가, 새로고침해도 남은 권수 유지, 한 줄 평 쓰기
7. 주소 옆 복사 아이콘으로 주소를 복사해 휴대폰으로 보내 열어 보세요.

### 배포 후 점검 프롬프트
```
내 서비스가 https://(내 주소).vercel.app 에 배포되었어. 휴대폰과 컴퓨터에서 확인할 점검 목록을 만들어 줘. 아래를 꼭 넣어 줘.
- 첫 화면과 책 카드(표지 사진, 손글씨 제목)가 보이는가
- 빌리기가 구글 시트에 저장되고, 새로고침해도 남은 권수가 유지되는가
- 한 줄 평이 시트에 저장되고, 승인(O)한 글만 카드에 보이는가
- 휴대폰에서 글자나 버튼이 잘리지 않는가
```

### 고쳐서 다시 올릴 때 (자동 재배포)
```
변경 내용을 커밋하고 GitHub 에 push 해 줘. push 한 뒤 Vercel 이 자동으로 다시 배포하니까, 1~2분 뒤 내 주소에서 무엇을 확인하면 되는지 한 줄로 알려 줘.
```
